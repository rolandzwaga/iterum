## Implementation notes — deviations reported by task agents

Each deviation below was reported by the executing task agent and is recorded here rather than being smoothed over. None of them changed a spec threshold downward.

### T001 — BrownianDrift (`brownian_drift.h`, `brownian_drift_test.cpp`)

- **Deliberate tightening of the plan.** `plan.md` 1.1 sets the output-smoother target to `depth*x` unclamped; the implementation clamps it: `std::clamp(depth_*x_, -1, 1)`. Reason given: the SC-002 analytic proof requires `|current-target| <= span = 2`; the ±4 walk-divergence guard would otherwise permit a target of 4 and a worst-case per-sample delta of ~3.5e-3, breaking the 2.0e-3 threshold. With the clamp the bound is `2*(1-coeff) = 1.39e-3` at 48 kHz. Reported bias impact nil at tested settings (clip probability ~0.1%).
- **Single-owner allocation-override rule.** `brownian_drift_test.cpp` is the sole TU in `dsp_processors_tests` that includes `<allocation_operator_overrides.h>`; the other five include only `<allocation_detector.h>`. A second include would be a duplicate-symbol link error.
- **Runtime cost.** The suite renders roughly 4500 s of audio (mostly `BrownianDrift_AutocorrTimeTracksSmoothness` at 100×tau and the 8-seed × 2-rate SC-005 case).
- **Cleanup.** Six zero-byte shell-redirect artefacts were removed from the repo root by this agent.

### T002 — BreathingModulator

- No deviations from the task spec. One self-review correction: the first shape test used argmin/argmax to locate trough/peak, which is wrong (the extrema are flat and the smoother lags, causing a `size_t` underflow with `troughIdx=95996` vs `peakIdx=38396`). Replaced with a band-entry marker; measured 0.3993/0.6007 at both sample rates.

### T003 — TidalModulator

- **Deviation 1 (estimator choice).** The task sketched "dominant period via first autocorrelation maximum / FFT peak". First-autocorrelation-maximum is unusable because FR-033 mandates equal layer weights, so all six spectral lines are equal-amplitude and shallow spurious maxima appear near `u = 1.3-1.5`. A direct DFT amplitude scan over ±15% around the predicted `P_base` was used instead. The ±6% tolerance is derived (bin width ±2.5%, unresolved +2% detune partner, ±0.6% scan grid), not guessed.
- **Deviation 2 (rate grid consequence).** Kept the specified rates {0.2, 0.5, 1.0}; at rate 0.2 the sqrt2/sqrt3 layers were originally frequency-degenerate, so the per-layer spectral probe runs only at rate 1.0. The load-bearing FR-033 bound is asserted as the exact identity `kNumLayers*kLayerWeight*kSinesPerLayer*kSinePairScale == 1`, and ratios are checked against independently computed `std::sqrt(2.0f)`/`std::sqrt(3.0f)` rather than the header's own literals, so the check is not tautological.
- **API change from the sketch.** `kNumLayers`, `kSinesPerLayer`, `kLayerWeight`, `kSinePairScale`, `kLayerRatios`, `getBasePeriodSeconds()` and `getLayerPeriodSeconds(size_t)` were made public — required because the task mandates asserting `sum|w_k| = 1` directly, which is unassertable without public constants.
- **Post-audit fix (FR-032).** The rate→period anchor was subsequently re-based on `kMaxBasePeriod = kMaxPeriod / kLayerRatios[kNumLayers-1]` (`tidal_modulator.h:156-157`) so the clamp is inert at every rate, and `TidalModulator_LayerRatiosHoldAtEveryRate` now asserts realised periods over 21 rate points.

### T004 — OrbitModulator

- **Judgement call 1.** `kRadiusRate` had no number in the plan; 0.1 units/second was chosen (full 1.0 → `kRadiusMin` in 9.5 s) and documented. The `growth=-1` edge-case test derives its settle time from the constant rather than hardcoding seconds, so a later retune does not silently break the test.
- **Judgement call 2.** The SC-002 header comment records the plan's stated bound (6.5e-5/sample) *and* refines it: at max coupling the phase derivative is `omega_max + k_max = 4.14 rad/s` → 8.6e-5/sample, plus ~9.3e-5 of smoother lag response. The test exercises the max-coupling case, so the recorded justification matches what is asserted.

### T005 — SplineTrajectory

- **Design note (deliberate).** No `OnePoleSmoother`. Output is evaluated per sample from `q(u)` so the signal is genuinely C1; a smoother would add lag and decimating through it would produce a staircase. The `std::clamp` in `updateOutput()` is inert (Lebesgue 1.25 × `kWaypointMax` 0.8 = 1.0), which is what preserves C1. `prepare()` floors the sample rate at 1 Hz so `du_` can never be infinite.
- **Deviation flagged by the agent.** The FR-053 second difference is formed on a **decimated** grid (stride 240), not per sample: at 48 kHz / 0.5 s spacing `du = 4.17e-5`, so a per-sample d2 is O(5e-9) — an order below float quantization (~1e-7), i.e. pure noise. With stride 240 the curvature term is 6.55e-4 while a slope kink lands near 2.4e-2.
- **Injected-bug check.** A C0 linear-interp variant gives ratio 401664 and `interiorMax` 5.96e-8 — rejected by *both* assertions. The detector has teeth.

### T006 — GrowthEnvelope
