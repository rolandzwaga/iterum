### Deviations and judgement calls reported by task agents

- **T004 → FR-080 budget expression.** The originally-specified budget `D = period − 1 − 0.55·dLoss − 0.96·dDisp` was measured to miss SC-009c (+5.26 / −8.17 cents at ±12 st) and a 15-point constant scan found no pair meeting 5 cents. The shipped form is `D = period − 1 − dLoss − dDisp − dDC`, worst case 1.50 cents, with the measurement table carried at waveguide_string.h:464-486.
- **T007 → OQ-E / SC-011(β).** Sub-64 partitions diverged by 7.1e-2 because `ModalResonatorBank::smoothCoefficients()` runs once per `processBlock` call. Resolved by option (c): a strictly-additive `snapCoefficients()` on the shared Layer-2 header, zero added latency, plus spec RA-5. Options (a) 64-sample latency and (b) a 1e-1 bound were both rejected.
- **T007/T011 → spectral estimator window.** SC-003(c) peak detection and SC-009(b) fundamental detection analyse the **free ring**, not the driven steady state. One 8192-point window of a noise-driven resonator put Glass's argmax 71 cents off and moved it with the seed (the complex amplitude random-walks ~50 % across the window). Same estimator, same FFT size, different source window; clauses (a) and (d) still use the driven window as specified.
- **T012 → zero-elapsed retarget path.** `setMaterial` re-targets in place when a fade has not yet advanced one control step, instead of collapsing — otherwise a material the listener never heard would occupy the sounding slot for 10 ms and ring out for 500 ms. Refused when the requested engine instance is the one the outgoing slot is ringing on.
- **T012 → collapse gain law.** Implemented as position interpolation rather than an element-wise multiply of the frozen pair, which either never reaches (0,1) or overshoots by 2.3 dB mid-ramp. `crossfadePos_` still stands still during the collapse, as FR-024a requires.
- **T012 → crossfade position arithmetic.** `elapsedSamples * crossfadeIncrement(...)` rather than a float accumulator: 1/24000 is not representable, and a one-ULP shortfall costs a whole extra control chunk of double-engine advance, which SC-016 measures to the sample.
- **T014 → FR-070a vs SC-009(b).** The default seed's mode-0 detune is +2.59 cents; added to Ice's +2.43 cents at 440 Hz that is 5.02 against a 5.0 bound. The bound was **not** widened — the deterministic seed term is recomputed independently from `core/random.h` and subtracted, so a wrong constant or a walked generator still fails.
- **T014 → output finiteness guard.** The two final output writes are zero-substituted. FR-038a can only act at the control step ending the chunk in which state went non-finite, by which time those samples have left `renderSub`. Documented as a finiteness guard only — not a level control, not a replacement for FR-037's clamp.
- **T014 → FR-038a clause order.** Control state is recovered before engine state: `WaveguideString::retune` neither rejects nor repairs a non-finite `f0` (`f0 < kMinFrequency` is false for NaN, and `std::clamp(NaN, …)` returns NaN), so retuning to a poisoned `bodyHz_` would brick the string on the very path meant to unbrick it.
- **T014 → SC-013(b2) windows and materials.** AGC disabled (a 190 dB transient's 200 ms release is the AGC working, not a latch); the ±1 dB convergence window is the final second of an 8 s render, not the first 100 ms (no resonator with a multi-second T60 can recover in 100 ms — passing such a clause would mean the tail had been destroyed); the "never false" clause covers Strings and Chamber, because on modal materials a ±1e38 block is a genuine FR-038a event.
- **T015 → SC-011 excitation.** A 220 Hz sine, not seeded noise: Xorshift32 carries PSD σ²/fs per Hz, so a resonator's output power falls as 1/fs by construction — ~3.4 dB between 44.1 and 96 kHz against a ±1 dB criterion, with nothing wrong in the component.
- **T003 → RA-4 parameter units.** `setModDepth` takes percent; the test uses 50.0 f (normalised 0.5), not the literal `0.5f` in the task text, which would have been normalised 0.005 and made the clauses trivial.
